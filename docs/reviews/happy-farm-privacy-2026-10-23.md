# 행복 농장 타이쿤 개인정보 처리방침 검토

[Happy Farm #520](https://github.com/seorilabs/happy-farm/issues/520)의 승인 설계와 동일 커밋의 test-plan.json에 따라 제품별 한국어와 영어 초안을 준비한다. 이 저장소는 main 병합 즉시 배포되므로 Ready PR에서 멈춘다. **이 PR을 병합하지 않는다.** 미확정 항목을 확인하기 전에는 공개 가능한 최종 방침이 아니다.

## 근거와 범위

Happy Farm 소스 3cb6e7b7e4ae8c3fe06268ec521104cfc21f5603과 Platform 소스 b0e053423f74f107b5fb7d3c991c924fd9370b49, Firebase 및 Google Mobile Ads 공식 문서로 처리 항목을 대조했다. 인증 토큰과 서비스 세션, 플랫폼 이용자 키와 별도 분석 식별값, 로컬 농장 초기화와 서버 기록 삭제를 구분했다. 비개인화 광고가 식별 정보를 사용하지 않는다는 보장은 넣지 않았다. Remote Config, Crashlytics, 클라우드 저장 및 결제를 사용한다고 쓰지 않았다.

## 공개 전 확인 항목

이 초안은 확인된 사실을 검토할 자료이며, 원 #520의 처리 항목과 보관 기간 인수조건 전체를 충족한 최종 고지가 아니다. 공식 사이트 Ready PR까지만 작성하고 병합하지 않는다. 공개 경로 및 스토어 URL을 교체하지 않는다.

- 개인정보보호위원회 2026년 4월 작성지침의 처리 목적과 근거, 보관 기간, 파기 절차, 위탁, 해당 시 국외 이전 및 아동 항목과 대조했다. 이 초안은 아직 해당 항목을 모두 충족하지 않아 공개 가능한 최종 방침으로 표시하지 않는다.
- GA4 속성의 실제 보관 설정은 조회 권한 403으로 확인하지 못했다. BigQuery 60일과 구분하고, GA4 분석 원본과 분석 식별 정보의 실제 삭제 절차도 별도로 확인한다.
- Platform 광고 보상 기록의 90일 ttlAt는 소스에만 있다. 광고 보상 및 이벤트 기록 각각의 운영 보관 정책과 TTL, 배포된 revision, 실제 삭제 주기와 성공, 요청 시 삭제 절차는 미확인이다.
- 처리 수탁사, 국외 처리 국가, 이전 항목, 목적, 시점과 방법, 보관 기간 및 적용 근거를 운영 자료와 법률 검토로 확정해야 한다.
- Firebase 익명 인증의 실제 삭제 절차와 서비스 이용자의 삭제 요청 경로를 점검한다. 농장 초기화는 서버 삭제가 아니다. 현재 본문은 확인된 문의 연락처만 안내하고 미확인 권리 처리 결과나 통지를 보장하지 않는다.
- 현재 iOS 분석 SDK의 광고 식별 지원과 TCF 보존 흔적, 미확인 추적 보장 문구는 #575 조사 항목이다. 비개인화 광고와 무식별 처리, 제한적 광고를 같은 의미로 쓰지 않는다.
- 대상 연령과 아동 관련 의무, 법률상 처리 근거, 삭제 요청 안내의 실제 운영 가능성을 확정한다. 평점 FOUR_PLUS로 이용 대상 연령을 추정하지 않는다.
- 개발 런타임 검증은 공개 200이나 운영 SDK 수집 범위 검증이 아니다.

사용자가 2026-10-23 운영 확인 자료가 없다고 답해 미확정 항목을 공개 전 확인 조건으로 유지한다. 초안 본문에는 운영 주기나 국가를 임의로 채우지 않았다.

## 원 이슈 인수조건

1. 두 공식 공개 URL의 200 응답은 미실행이다. localhost와 로컬 빌드는 공개 근거가 아니다.
2. 실제 SDK와 처리 항목을 대조했으나 보관 기간과 국외 처리 정보가 미확정이다. 전체 충족으로 표시하지 않는다.
3. 사용하지 않는 기능을 추가하지 않고 회사 공통 방침을 복사하지 않았다.
4. 제품 legal, 한국어 및 영어 법률 문서 인덱스와 sitemap 등록은 로컬 빌드에서 확인한다.
5. registry 경고 제거는 로컬 검사에서 확인한다.
6. Happy Farm config의 privacyPolicyUrl 변경은 제외한다.
7. Google Play 및 App Store Connect URL 변경은 제외한다.
8. 회사 공통 방침 소스를 바꾸지 않는다. 공개 운영 상태는 이 PR의 로컬 검사와 구분한다.

`npm run check`에서 Svelte 오류와 경고는 0건이고 registry 검사가 통과했다. 기존 다른 제품 8개의 제품별 방침 누락 경고에는 happy-farm이 없다. `npm run build`와 후속 검사에서 페이지 81개, 고정 URL 34개, 한국어와 영어 방침 및 sitemap을 확인했다.

320폭의 로컬 런타임에서 두 언어의 8개 절과 본문, 언어 전환, 목차 앵커, 하단 링크 및 법률 문서 인덱스를 확인했다. 회사 공통 방침 소스 3개는 기준과 바이트가 같다. 웹사이트 분석 배너를 거부한 실제 입력 뒤 문서가 가려지지 않는 화면을 확인했다. 초기 배너가 가린 캡처는 완료 근거로 쓰지 않는다. 최종 후보와 증적 NAS 경로는 PR에서 연결한다. 새 디자인이나 공통 화면을 만들지 않고 기존 LegalDocPage를 재사용한다.
