## 적용 범위와 화면

사용 흐름은 Google Play의 서비스 약관 링크를 열고, 공통 약관을 읽거나 **적용 앱**으로 이동한 뒤, 해당 앱의 별도 약관이 있으면 확인하는 순서다. 한국어 링크는 기존 언어 전환으로 연결한다. 방문자는 앱 로그인 없이 두 문서를 읽을 수 있다.

적용 앱은 [공식 사이트 카탈로그](https://www.seorilabs.com/en/apps/)에서 `live`로 표시한 앱과 게임에서 가져온다. 공개 예정이거나 공식 카탈로그에서 별도로 관리하는 제품을 목록에 넣으려면 운영 범위를 먼저 확인한다. 별도 약관이 있는 앱도 공통 약관을 적용하되, 충돌하는 항목은 해당 별도 약관을 따른다. Reascend의 만 18세 이상 조건은 기존 문구를 별도 항목에서 유지한다. 별도 약관 원문과 주소는 계속 제공한다. 변경 범위는 공식 사이트의 웹 문서 공개다.

## 구조와 운영

- 기존 두 정적 주소와 `LegalDocPage`를 사용한다. 문서에 적용 앱 목록 항목을 추가해 제품명, 등록된 패키지 ID, 별도 약관 링크를 서버에서 미리 렌더링한다. JavaScript 실행에 앞서 HTML에서 내용을 읽을 수 있다. 계약·결제 시스템이나 사용자 데이터는 연결하지 않는다.
- `src/lib/products/registry.ts`를 앱 이름·채널·앱별 URL의 정본으로 쓴다. 사용자에게는 목록을 읽거나 직접 검색할 수 있는 HTML 텍스트로 제공하고 작은 화면에서는 패키지 ID가 화면 폭에 맞춰 줄바꿈되게 한다. 링크와 언어 전환은 키보드로 접근 가능해야 한다.
- 별도 페이지를 앱마다 새로 만드는 방식은 Play 입력 주소가 하나여야 한다는 요구와 맞지 않는다. 공통 본문과 기존 앱별 약관 링크를 한 페이지에 함께 제공한다. 새 앱에 이 주소를 등록하기 전에 적용 앱 목록에 해당 앱이 들어 있는지 확인한다.
- 공개 도메인과 GitHub Pages의 기존 정적 배포를 사용한다. URL, 언어 전환, 앱별 링크에 회귀가 생기면 주소를 유지하고 이전 내용을 복구하는 PR을 적용한다.

## 인수조건과 테스트

| 조건                                        | 실행과 통과 기준                                                                                                                                                                                                                              |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-1. 같은 영어 주소에서 서비스별 적용 확인 | 새 조건을 검사하는 빌드 단언이 현재 산출물에서 실패하는지 먼저 확인한다. 두 언어의 정적 HTML에서 적용 대상 이름과 패키지 ID, 도마뱀 테라리움과 운글 문서 링크, 공통 조항이 모두 있는지 확인한다. Reascend 연령 조건은 해당 제품으로 한정한다. |
| AC-2. 기존 사이트 전체 회귀                 | `npm run check`, `npm run build`로 타입, 제품 목록, 전체 고정 URL·사이트맵·정적 산출물을 검사하고 기존 기능 목록의 전체 여정을 개발 브라우저에서 확인한다. 두 약관의 언어 전환과 키보드 링크를 데스크톱과 모바일 폭에서 확인한다.             |
| AC-3. 공식 주소 공개                        | 중앙 `web before-deploy` 검증을 통과하고 GitHub Pages에서 공개한다. 공개 후 로그인 없는 요청에서 HTTPS 인증서 검증과 HTTP 200, `text/html`, 언어·앱 식별자·앱별 링크를 확인한다.                                                              |

[테스트 계획](test-plan.json)은 기존 법적 문서 템플릿이 여럿의 페이지를 렌더링한다는 점을 반영해 L3 개발 환경으로 잡는다. 같은 주소와 화면 구조에서 문구와 목록을 갱신한다. 출시 범위는 공식 웹사이트 공개다. Google Play는 이용자가 링크를 발견하는 경로이며 테스트 계획의 출시 마켓은 웹이다.
